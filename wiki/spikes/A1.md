# A1 — Skills in a restricted `ask` session through the confined `read_file`

**Verdict: PASS, with one change to how skills are loaded.** A session whose tools are exactly `web_search`, `list_files`, `read_file`, `write_file` and `yield` lists the admin's skills in omp's own system prompt as soon as the custom `read_file` declares `readsSkillUris: true`. Given a question that named neither the skill nor a URI, `claude-haiku-4-5` read `skill://glossary`, then `skill://glossary/terms.md`, and answered from the skill's extra file. omp does not intercept `skill://` for custom tools: the raw URI reaches `execute`, so the confinement is entirely ours. The AGT-30 fallback (a host-built catalog) is not needed.

The change: AgentBot's session options (the omp dir as the only extension root, `disableExtensionDiscovery: true`) do **not** make the omp dir the only skill source. omp's skill discovery still reads the agent dir, `~/.agents`, and the cwd's `.omp`, `.claude` and `.agents` folders. Phase 4 must pass the skill list explicitly (`createAgentSession({ skills })`), which turns omp's skill discovery off.

Plan's "Pass when": *The system prompt lists the skill, and the agent reads `skill://<name>`.* Observed: both.

## Question

Can a restricted `ask` session list and load skills through the confined `read_file` (AGT-30), with no omp `read` or `bash`?

## How omp handles skills (SDK read, 18.12.1)

Paths are relative to `node_modules/@oh-my-pi/pi-coding-agent/src`.

- **The listing gate.** `buildSystemPrompt` lists skills only when an active tool declares `readsSkillUris === true`, whatever the tool's name (`system-prompt.ts:919-939`, `toolReadsSkillUris` at `:445`). The same flag turns on the `skill://` scheme doc line (`internal-urls/skill-protocol.ts:130`, via `skillUriAccess`). omp's own `read` and `bash` declare it (`tools/read.ts:977`, `tools/bash.ts:503`).
- **Custom tools carry the flag.** It is a `CustomTool` field (`extensibility/custom-tools/types.ts:211`), and `customToolToDefinition` copies it to the tool definition (`sdk.ts:1414`). The mid-session `/skillful` path uses the same check (`session/agent-session.ts:10721`), and the tool signature includes it so a change rebuilds the prompt (`session/session-tools.ts:2186`).
- **The `skillful` setting.** It defaults to `true`. With `false`, omp passes no skills to the prompt (`sdk.ts:4043`). AGT-20 lets the admin override any setting, so AskBot must pin it.
- **The URI is not intercepted.** `CustomToolAdapter.execute` passes `params` through unchanged (`extensibility/custom-tools/wrapper.ts:32-39`). omp's `skill://` handler (`SkillProtocolHandler`, `internal-urls/skill-protocol.ts`) is used only by omp's own tools. The spike's tool logged the raw `"skill://glossary"` (below).
- **Where skills come from.** If `options.skills` is undefined, `createAgentSession` runs `discoverSkills` → `loadSkills` with the `skills.*` settings (`sdk.ts:1881-1890`, `extensibility/skills.ts:289-340`). That loads every skill provider. The explicit extension root contributes its `skills/` as source `omp-plugins:user`. `disableExtensionDiscovery` ("explicit-only" roots, `sdk.ts:1726`) limits extension/plugin roots only; the native, `agents` and `claude` providers still scan the agent dir, `$HOME` and the cwd. If `options.skills` is set, discovery is skipped (`sdk.ts:1884`, `:2145-2146`) and later rediscovery is off (`skillsReloadable: options.skills === undefined`, `sdk.ts:4718`, guard at `session/session-tools.ts:1787`).
- **Description shown.** The catalog shows `previewSkillDescription` (whitespace collapsed; over 100 characters, cut to the first sentence or word boundary, `extensibility/skill-descriptions.ts:113-121`). omp can also compress descriptions with a `smol` model call in the background, but only when the session's `agentDir` differs from the process agent dir (`sdk.ts:3854-3857`; without a store, nothing is scheduled, `skill-descriptions.ts:349-354`). The worker sets `PI_CODING_AGENT_DIR` to the run's agent dir, so the worker never makes that model call. Admins should keep descriptions under 100 characters to avoid truncation.
- Frontmatter `hide: true` (or `disableModelInvocation: true`) leaves a skill out of the listing; it stays readable (`extensibility/skills.ts:265`).

## What was built

`spikes/a1/`. Run it with `bun spikes/a1/run.ts` (about 10 s, about $0.015).

- `run.ts` builds a temp sandbox, then deletes it at the end. The sandbox has:
  - `omp/skills/glossary/SKILL.md` (frontmatter `name`, `description`) and `glossary/terms.md` (the definition and the code word `ZEBRA-42`);
  - a sibling skill `omp/skills/other`;
  - a symlink `glossary/leak.md` → `secret.txt` outside every root;
  - decoy skills in every default discovery location: `$HOME/.omp/agent/skills`, `$PI_CODING_AGENT_DIR/skills`, `$HOME/{.claude,.agents,.codex}/skills`, and `<cwd>/{.omp,.claude,.agents}/skills`.

  It starts `child.ts` twice with `HOME` and `PI_CODING_AGENT_DIR` in the sandbox, the scratch directory as cwd, and no `PI_*`/`OMP_*` variables, as the worker starts the agent host (S2). The developer's `~/.omp/agent` is used only to open the sign-ins (`discoverAuthStorage`), as `scripts/dry-run.ts` does.
- `skillTools.ts` contains `list_files`, `read_file` and `write_file`, copied from `src/worker/host/scratchTools.ts` (text files only) and changed as follows:
  - `resolveToolPath` maps `skill://<name>[/<rel>]` to `resolveInside(<ompDir>/skills/<name>, rel || ".")`. The skill's folder is the confinement root, so `..` cannot reach a sibling skill. The name must match AGT-25's `^[a-z0-9][a-z0-9-]{0,63}$` and be an existing directory.
  - `read_file` serves `SKILL.md` for the folder, and declares `readsSkillUris: true`.
  - `write_file` refuses `skill://` with "skills are read-only".
  - Every raw `path` argument is recorded.
- `child.ts` creates the session with `session.ts`'s options for the ask profile: `toolNames` + `restrictToolNames`, `customTools`, `allowRestrictedCustomTools`, `disableExtensionDiscovery`, `additionalExtensionPaths: [ompDir]`, `enableMCP: false`, `requireYieldTool` with an output schema. Settings come from `Settings.init({ inMemory: true, … })` with the AGT-20 pins.
  - `A1_MODE=discover` creates the session exactly so and prints what omp loaded; it makes no model call.
  - `A1_MODE=explicit` runs the direct tool checks, adds `skills: loadSkillsFromDir({ dir: <ompDir>/skills, source: "askbot:user" }).skills`, and runs one real turn on `anthropic/claude-haiku-4-5`. The prompt is: *What does the team term "flarn" mean, and what is its code word? Answer in one sentence.*

What this shows:

- **Listing:** with only the custom `read_file` declaring `readsSkillUris`, omp rendered its `# Skills & Rules` block and the `skill://` doc line. There was no `read` or `bash` in the session.
- **Loading:** the model followed omp's catalog on its own. It read `skill://glossary`, then resolved "`terms.md` in this skill's folder" to `skill://glossary/terms.md` from omp's one-line doc ("append `/<path>` for a file").
- **No interception:** `execute` got the literal `skill://…` strings.
- **Confinement:** `..` out of the skill folder, a sibling skill, a symlinked file, an absolute path after the name, an unknown or decoy skill name, and other schemes were all refused. `write_file` refused `skill://`. `list_files skill://glossary` does not list the symlink (`Dirent.isFile()` is false for it).
- **No decoys:** with `skills:` set, `session.skills` and the prompt contained only the omp dir's skills.
- The full prompts are written to `spikes/a1/out/system-prompt.{discover,explicit}.txt`.

## Phase 4 mechanism

**1. Load the skills explicitly** (`src/worker/host/session.ts`, `createAgentSession` for the ask profile):

```ts
import { loadSkillsFromDir } from "@oh-my-pi/pi-coding-agent/extensibility/skills";

const { skills } = await loadSkillsFromDir({ dir: join(runtime.ompDir, "skills"), source: "askbot:user" });
created = await createAgentSession({
	// …as now, including additionalExtensionPaths: [runtime.ompDir] and disableExtensionDiscovery: true (agents, A2)
	skills, // AGT-24: the omp dir is the only skill source; turns omp's skill discovery and rediscovery off
});
```

- `loadSkillsFromDir` is not re-exported from the package root, but it is reachable through the package's `./*` export. If a later omp drops it, build the objects directly from the worker's own AGT-25 check: `{ name, description, filePath: <dir>/<name>/SKILL.md, baseDir: <dir>/<name>, source: "askbot:user" }` (`Skill`, `extensibility/skills.ts:31-49`).
- AGT-27's loadout reads `session.skills`, which is then exactly this list.

**2. `read_file` and `list_files` accept `skill://`** (`src/worker/host/scratchTools.ts`):

```ts
const SKILL_URI = /^skill:\/\/([^/]*)(?:\/(.*))?$/;
const SKILL_NAME = /^[a-z0-9][a-z0-9-]{0,63}$/;

async function resolveToolPath(roots: { scratch: string; skills: string }, path: string): Promise<{ abs: string; skill: boolean }> {
	const m = SKILL_URI.exec(path);
	if (!m) return { abs: await resolveInside(roots.scratch, path), skill: false };
	const [, name, rel = ""] = m;
	if (!SKILL_NAME.test(name)) throw new Error(`Invalid skill name in ${path}`);
	const skillDir = join(roots.skills, name);
	if (!(await lstat(skillDir).catch(() => undefined))?.isDirectory()) throw new Error(`No such skill: ${name}`);
	return { abs: await resolveInside(skillDir, rel === "" ? "." : rel), skill: true };
}
```

- `read_file`: `readsSkillUris: true`. If the resolved skill path is a directory, read `resolveInside(abs, "SKILL.md")`.
- `list_files`: for a `skill://` path, show entries relative to the skill folder.
- `write_file`: `if (SKILL_URI.test(path)) throw new Error("skills are read-only")`.
- `resolveInside` stays as it is; `URL_SCHEME` keeps refusing every other scheme.
- Mention `skill://<name>` in the `path` parameter descriptions. The spike did; omp's catalog line was enough by itself, but the tool schema should not contradict it.
- `createScratchTools(root)` takes the skills root as well (`<ompDir>/skills`).

**3. Pin `skillful = true`** in `LOCKED_SETTINGS` (`src/shared/ompconfig.ts`). This is AGT-20's pinned list; reason: "the skill list in the prompt is how /ask finds the admin's skills (AGT-30)". Without the pin, an admin override `skillful: false` silently empties the catalog (`sdk.ts:4043`). The `skills.*` settings need no pin: with `skills:` set they are never read.

## Consequences for the plan

- AGT-30 holds as written. No fallback is needed, and `wiki/requirements.md` §16 is unchanged.
- Suggested wording changes (not applied; the spike contract changes requirements only on failure):
  - **AGT-20:** add `skillful = true` to the pinned settings.
  - **AGT-24:** "loads it as the session's only extension root" → "loads it as the session's only extension root, and passes its skills to omp explicitly so that omp's skill discovery (agent dir, `$HOME`, cwd) is off".

## Not tested

- Task subagents (A2). Whether a `task` subagent inherits the parent's explicit `skills` or rediscovers them must be checked there.
- Images, PDF and other converted formats under `skill://`. The code path is the same as for scratch files once the path has resolved.
- Paging (`offset`/`limit`) on a skill file, and a skill whose `SKILL.md` is missing (`read_file skill://x` then gives "No such file").
- A model other than `claude-haiku-4-5`.
