# A2 — Task agents in a restricted `ask` session

**Verdict: PASS, with three host-side conditions.** omp 18.12.1's own `task` tool can run AskBot's task agents. A restricted `ask` session spawned only the admin's valid agent. The child had exactly its frontmatter tools (`web_search`). It could not spawn further agents. The parent's usage included the child's, and aborting the parent stopped the child within 25 ms. The `run_agent` fallback in implementation.md §3 is not needed.

AgentBot's session options alone are **not** enough. Phase 4 must also do the following:

1. **Pass `spawns`.** Set `createAgentSession({ spawns: "<valid agent names>" })`. Without it, the session spawns omp's six bundled agents, agents from the agent dir and from the cwd's `.omp/agents`, and `m1`. omp creates `m1` when the user's prompt contains `^provider/model`.
2. **Move the cwd out of the scratch dir.** omp looks up agents by name, and agents in the cwd's `.omp/agents` take precedence over the extension root. `write_file` can write there. The spike planted `.omp/agents/researcher.md` with `tools: bash, read`, and spawning `researcher` then gave the child `bash`. Spike A1 found the same leak for skills.
3. **Drop invalid agents in the worker before the session starts (AGT-25).** omp gives a child whatever its frontmatter names, including `bash`.

AGT-20 gains one pin: `task.maxRecursionDepth = 1`. `task.disabledAgents` is not needed.

Plan's "Pass when": *Only admin agents spawn; the child has no tool outside its frontmatter allowlist; the parent's usage includes the child's.* Observed with the three conditions in place:
- Only `researcher` was listed or spawnable. Eleven other names were refused at preflight, and no session was created for them.
- The child's active and sent tools were `[web_search]`, and it called `web_search`.
- The parent's `getSessionStats()` grew by exactly its own calls plus the child's calls.

## Question

Can omp's `task` tool, in a restricted session whose only extension root is the downloaded omp dir, meet the following requirements?

- Spawn only the admin's agents (`agents/<name>.md`), never omp's bundled agents or agents found elsewhere (AGT-31).
- Give the child only its frontmatter tools.
- Keep children from spawning (AGT-31).
- Count child usage in the turn's usage and cost (AGT-32).
- Abort children with the turn (AGT-32).

## How omp does it (SDK read, 18.12.1)

Paths are relative to `node_modules/@oh-my-pi/pi-coding-agent/src/`.

### Where agents come from

`discoverAgents` (`task/discovery.ts:86-177`) builds the list in this precedence order, and the first match by name wins (`:157-168`):

1. The project's `.omp/agents`. `findAllNearestProjectConfigDirs` walks up from the cwd to `/` (`config.ts:218-247`).
2. The user's `~/.omp/agent/agents`, which is run-local in a worker.
3. `<root>/agents` for each extension root. With `disableExtensionDiscovery`, only the explicit roots count (`discovery/omp-extension-roots.ts:275-277`).
4. Claude-marketplace and omp plugin roots, including a project registry `.omp/plugins/installed_plugins.json` found from the cwd (`discovery/helpers.ts:1388-1426`).
5. The bundled agents, which are always appended (`task/agents.ts:45-75`): `scout`, `reviewer`, `security-reviewer`, `seance`, `task` and `sonic`.

The session has no option to pass an explicit agent list. Spawns rediscover agents every time (`task/structured-subagent.ts:358`).

### Other agent sources

- **Session agents.** The session also offers agents named `m<N>` (`structured-subagent.ts:359`, `task/index.ts:739`). omp creates one whenever a user prompt contains `^<provider/model>` (`session/agent-session.ts:7601`). Each is a copy of the bundled `task` agent with omp's default tools (`session/model-mentions.ts:112-128`). In `/ask`, a public user writes that prompt.
- **Inherited skills.** A child gets the parent's skill list as an explicit `skills` option (`structured-subagent.ts:652`, `task/executor.ts:4488`). So once phase 4 passes `skills` (A1), the child does not rediscover skills either: `skillsReloadable` is false (`sdk.ts:4718`, `session/session-tools.ts:1787`). The `autoloadSkills` refresh (`structured-subagent.ts:562-568`) therefore cannot reach disk.

### The spawn policy

The `spawns` option is a session option, not a setting, so admins cannot override it. Its default is `"*"` (`sdk.ts:549`, `:2380`). `resolveSpawnPolicy` turns a comma list into an allowlist (`task/spawn-policy.ts:19-58`). The allowlist is checked in two places:

- The tool description lists only allowed agents (`task/index.ts:168-179`).
- Preflight refuses any other name with `Cannot spawn '<name>'. Allowed: …`, before discovery and before any child session is created (`structured-subagent.ts:285-308`).

`task.disabledAgents` is checked only after the name lookup (`structured-subagent.ts:369-378`).

### The child's tools

The child's tools come from `executor.ts:4085-4122`: `toolNames = agent.tools`, with these adjustments:

- `yield` is removed unless the run is structured. `task.structured` defaults to false.
- `task` is added when the agent has `spawns`, and removed at maximum depth.
- `exec` expands to `bash`, plus `eval` when available.
- `wait` is added for `task`/`bash` agents, unless the parent restricts tool names.

The child inherits `restrictToolNames` from the parent (`structured-subagent.ts:588`). For a restricted child:

- It gets no MCP, no preloaded extension or custom-tool paths (`:589`, `:662-664`), and no parent custom tools: `customTools` is only the call's eval-defined tools (`:649`).
- It gets no xd:// `write` transport, because that is only for unrestricted sessions with `read` (`tools/index.ts:876-892`).
- Nothing checks the frontmatter tools against any allowlist. `tools: bash` gives the child `bash`.

### Depth

`canSpawnAtDepth(max, depth)` returns `max < 0 || depth < max` (`task/types.ts:246-248`). `task.maxRecursionDepth` defaults to 2 (`task/settings.ts:331-334`). With 1, the top-level session (depth 0) can spawn, and its child (depth 1) is at maximum depth: `task` is stripped (`executor.ts:4088`, `:4101-4103`) and `spawnsEnv` is `""` (`:4132-4138`).

### The `tools` field of a `task` call

This field asks for eval-kernel tools. It goes to `describeEvalTools` (`task/index.ts:957-969`, `task/eval-tools.ts:85-105`):

- With `eval.tools.enabled=false`, the call is refused.
- Otherwise, any name that no eval kernel defines is refused. The `ask` profile has no `eval` tool, so no kernel defines any.

### Usage

`SessionStatsTracker` adds each `task` tool result's `details.usage` to the parent's tokens and cost (`session/session-stats.ts:171-177`, `:220-228`, `:499-503`). Child usage therefore reaches `getSessionStats()`, which is what `createUsageMeter` reads, once the `task` call returns. Before that, it is visible only on the subagent event bus, as `task:subagent:event` frames carrying the child's `message_end` events (`executor.ts:1711-1714`). This bus is the `subagentEventBus` session option, which children inherit (`sdk.ts:741`, `executor.ts:4503`).

### Abort

The `task` call's signal is the parent's tool signal. When it aborts, the executor aborts the child session (`executor.ts:4702-4714`). `async.enabled=false` (already pinned) makes every spawn synchronous, so child time falls inside the parent's turn.

## What was built

`spikes/a2/`. Run it with `bun spikes/a2/run.ts`.

**`run.ts`** creates a temp sandbox and starts `spike.ts` with `HOME` and `PI_CODING_AGENT_DIR` pointing into it, as a worker starts its agent host (S2). It deletes the sandbox afterwards. The sandbox contains:

- `omp/agents/`, the extension root: `researcher.md` (`tools: web_search`), `shell.md` (`tools: bash`) and `spawner.md` (`tools: web_search`, `spawns: researcher`).
- Decoys: `$PI_CODING_AGENT_DIR/agents/user-rogue.md` and `scratch/.omp/agents/project-rogue.md`, both `tools: bash`.
- `scratch/{inputs,outputs}` and a separate `work/` dir.

**`spike.ts`** opens the developer's sign-ins with `discoverAuthStorage(~/.omp/agent)`, as `scripts/dry-run.ts` does, and uses `anthropic/claude-haiku-5-5`. Every session is AgentBot's `ask` setup:

- tools `web_search`, `list_files`, `read_file`, `write_file`, `yield` and `task`, with the real `createScratchTools` from `src/worker/host/scratchTools.ts`;
- `restrictToolNames`, `disableExtensionDiscovery`, and `additionalExtensionPaths: [ompDir]`;
- AgentBot's pinned settings and `requireYieldTool`.

The spike calls the session's own `task` tool directly for deterministic probes (same `#dispatch` → preflight → executor path as a model call). It also runs two real model turns. It observes children through `subagentEventBus` plus the global `AgentRegistry`. The registry attaches the child session only after the run settles, so subscribing there is too late for live events.

What this shows:

- **AgentBot's options alone leak agents (run 1).** `disableExtensionDiscovery` and the single extension root do not limit agent discovery. The `task` description listed the six bundled agents, the agent-dir decoy and the scratch-dir decoy. A `^anthropic/claude-haiku-5-5` mention in the prompt added `m1`, and spawning it worked.
- **The child gets its frontmatter tools verbatim.** `shell` (`tools: bash`) got `[bash]` and ran `echo`. Only the worker's AGT-25 filter can keep such an agent out.
- **The child does not inherit the parent's tools.** It had none of `list_files`, `read_file`, `write_file`, `task` or `yield`.
- **A scratch cwd lets the model replace an admin agent (run 2).** `write_file` wrote `.omp/agents/researcher.md` inside the scratch dir. The allowlist `spawns: "researcher"` still matched by name, and the project copy won over the admin's file. The child got `[bash, read]` and ran a shell command. Scratch persists across a thread's turns, so a file planted in one turn would be active in the next.
- **The proposed mechanism closes all of these (run 3).**
  - The cwd was a run dir the model cannot write, and `spawns` named the valid agents.
  - Only `researcher` was advertised; the system prompt named no other agent.
  - All 11 other names were refused at preflight, with no child created. The 11 were the bundled agents, the invalid admin agents, both decoys, and the user's `m1`.
  - The same planted file in the scratch dir no longer mattered, because the cwd was elsewhere.
  - The `tools` field of a `task` call granted nothing, with or without `eval.tools.enabled`.
- **The child had only `web_search`.** The model spawned `researcher` itself. The child's active tools and the tools sent to the model were both `[web_search]`, and it called `web_search`.
- **Usage adds up exactly.** In the real turn, the parent's stats growth equals its own calls plus the child's calls (input, output, cache and cost). `details.usage` of the `task` result equals the child's own `message_end` sum. AgentBot's `createUsageMeter` reads `getSessionStats()`, so OBS-05 needs no change.
- **Depth pin 1 removes `task` from children.** An agent with `spawns` got `[web_search]` under depth 1, and `[task, web_search]` under omp's default of 2.
- **Abort reaches the child.**
  - `session.abort()` on the parent ended the child 10 ms later (18 and 22 ms in earlier runs). The child's in-flight model call ended `aborted`, and the child made no further calls.
  - The child's completed calls ($0.00077) were still counted in the parent's stats.
  - A model call aborted mid-stream reported zero usage (an earlier run aborted 2.5 s into the child's first call: `stopReasons=[aborted]`, `cost=$0`). This is probably the same for the parent's own aborted calls, so not specific to subagents. That is an inference; the parent case was not run.

## Phase 4 mechanism

**1. Worker (`src/worker/runner.ts` / agent host): validate agents, then start the session.**

- Check every `<ompDir>/agents/*.md` against AGT-25. **Delete** each invalid file, and log `agent skipped` with the name and reason. Deleting the file, rather than only leaving it out of `spawns`, matters because omp keeps the first file of a given name within one dir.
- Also delete files whose name is not `<frontmatter name>.md`.
- Set the `ask` session's cwd to a run dir the model cannot write (e.g. `dirs.work`), never `dirs.scratch`. No ancestor of it may contain `.omp`. The scratch tools still get `scratchRoot` explicitly. Today the cwd is `dirs.checkout ?? dirs.scratch ?? dirs.work` (`runner.ts:548`).

**2. Session (`src/worker/host/session.ts`):**

```ts
const agents = validAgentNames; // from the worker's AGT-25 pass; [] → no task tool (AGT-08)
const subagentEvents = new EventBus(); // "@oh-my-pi/pi-coding-agent/utils/event-bus"
await createAgentSession({
	cwd: workDir,                              // not the scratch dir
	disableExtensionDiscovery: true,
	additionalExtensionPaths: [ompDir],
	skills,                                    // A1: explicit list
	toolNames: ["web_search", "list_files", "read_file", "write_file", "yield", ...(agents.length ? ["task"] : [])],
	restrictToolNames: true,
	spawns: agents.join(","),                  // allowlist: tool description + preflight
	subagentEventBus: subagentEvents,          // live child usage and progress
	settings,                                  // pins below applied last
	// …the rest as today
});
```

**3. Pins (`LOCKED_SETTINGS`, AGT-20).**

- Add `"task.maxRecursionDepth": 1`. Children then never get `task`, even if an agent with `spawns` slipped past validation. It also stops an admin override from turning `task` off (0) or allowing deeper spawns.
- Keep `async.enabled = false`: spawns stay synchronous, so the turn's wall clock covers subagent time and the turn abort covers the subagent.
- Do not pin `task.disabledAgents`. `spawns` already excludes bundled agents. Pinning bundled names would also disable an admin agent that reuses a bundled name; extension agents come before bundled ones, so the admin's file wins there.

**4. Limits and usage (AGT-14, AGT-32, OBS-05).**

- No change for totals: the usage meter already includes subagents once each `task` call returns.
- For the cost limit *while* a child runs, add the child's live usage from the bus. The child's own turns do not end the parent's turn.

  ```ts
  let childCost = 0;
  subagentEvents.on("task:subagent:event", data => {
  	const { event } = data as SubagentEventPayload; // type from "@oh-my-pi/pi-coding-agent/task"
  	if (event.type === "message_end" && "role" in event.message && event.message.role === "assistant") {
  		childCost += event.message.usage.cost.total;
  		if (meter.total.costUsd + childCost > opts.limits.costUsd) abortWith("cost");
  	}
  });
  // parent `tool_execution_end` with toolName "task": meter.update(); childCost = 0;
  ```

- `abortWith` → `session.abort()` already stops the child.
- The same bus frames can drive the progress line and transcript for subagent tool calls.

**5. Loadout (AGT-27).** List the agents as `validAgentNames` minus `task.disabledAgents`. Do not use the current `discoverAgents(…, { mode: "explicit-only" })` call in `src/worker/host/loadout.ts`: it always appends omp's bundled agents and ignores the cwd and agent-dir sources, so it does not match what the session can spawn.

**6. Validation additions (AGT-25).** The `tools` allowlist (`web_search`) already rules out `bash`, `exec`, `task` and `read`. Also refuse:

- the frontmatter keys `advisor` and `prewalk`. These attach another model loop to the child: `advisor` gets its own tool slate, which defaults to `read`/`grep`/`glob` (`advisor/advise-tool.ts:165`, `session/session-advisors.ts:1326-1328`). Not tested; refusing them is the safe default.
- `autoloadSkills` naming a skill that is not installed.

`model`, `thinkingLevel`, `blocking`, `structured`/`output` and `readSummarize` are harmless. `structured` gives the child `yield`, which AGT-31 allows as "what omp itself needs to return the subagent's result".

## Fragility

- **The mechanism uses public options only:** `spawns`, `subagentEventBus`, `toolNames`, `restrictToolNames` and the `task.maxRecursionDepth` setting. The only deep imports are `EventBus` (`utils/event-bus`) and the channel name `task:subagent:event` (`task/types.ts:35`). Neither is re-exported from the package root.
- **What a future omp release could break:**
  - the allowlist check moving after the name lookup (`structured-subagent.ts:356` vs `:358-360`);
  - a new agent source that is not gated by `spawns`;
  - a change to how the child's tools are derived (`executor.ts:4092-4122`);
  - `task` result `details.usage` no longer being added to the parent's stats.
- **Port the spike into `test/integration` in phase 4,** so that an omp upgrade that changes any of these fails CI (phase 8, UPD-06). The cases are: the advertised list, preflight refusals, the planted-file test, the child's tools, usage equality and abort.

## Consequences for the plan

These requirement changes are not applied, because the spike passed. The contract allows requirement edits only on a failed spike, and these clarify rather than replace the requirements.

- **AGT-20:** append "`task.maxRecursionDepth = 1` (spike A2)" to the pinned settings.
- **AGT-24:** add "The `ask` session's working directory is a run directory outside the scratch directory, so that files the agent writes cannot add skills or agents (spikes A1, A2)."
- **AGT-25:** add "The frontmatter MUST NOT contain `advisor` or `prewalk`."
- **AGT-31:** add "The session MUST name the valid agents as its only spawnable agents (omp's `spawns` allowlist). User-tagged model agents (`^provider/model`) MUST NOT be spawnable."
- **AGT-14 / AGT-32:** add "The cost limit counts a running subagent's usage as it accrues."
- **§16:** "Spike A2 passed; see `wiki/spikes/A2.md` for the required session options."

## Not tested

- Batch spawns (several `tasks[]` in one call) and parallel children. They use the same preflight per item (`task/index.ts:973-997`).
- `advisor`/`prewalk` frontmatter (see phase 4 item 6).
- Other `web_search` providers. The child used the default provider with the Anthropic sign-in.
- A real container or Podman. The worker's run-local `HOME`/agent dir was reproduced with a temp sandbox.
- Compaction inside a child, and `task.maxRuntimeMs`.
